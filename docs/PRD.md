# Relic — PRD

Self-hosted экосистема для закрытых Minecraft-серверов: серверный демон и лаунчер, оба на Rust. Цель — убрать рассинхрон модпака между сервером и клиентами, автоматизировать установку игры, держать собственную авторизацию и брендировать лаунчер с сервера.

Это исправленная версия исходного PRD. Отличия от оригинала собраны в разделе 7.

## 1. Компоненты

```
СЕРВЕР (VPS)                                  КЛИЕНТ (Windows / Linux / macOS)
admin-core (Axum, Tokio, SQLite)              launcher-client (GPUI)
  веб-админка (SPA, вшита в бинарь)             discovery (DNS SRV)
  supervisor: N MC-инстансов                    тема и контент с сервера
  инспектор JAR, blob-хранилище       <---->    установка MC, лоадера, JRE
  манифест клиента на инстанс        HTTPS      delta sync модпака
  Yggdrasil + скины                  REST+WS    запуск с authlib-injector
  тема лаунчера, новости                        самообновление
```

Транспорт: REST/JSON поверх HTTPS и WebSocket для событий. TLS обязателен.

## 2. admin-core

Один бинарь без внешних зависимостей; данные в одном каталоге (`relic.db`, `blobs/`, `instances/`, `backups/`).

### 2.1. Инстансы и supervisor
- Несколько MC-серверов на один `admin-core`. У каждого свой каталог, порт, лимит памяти, версия MC, лоадер и модпак.
- Каждый инстанс — дочерний JVM-процесс. Консоль (stdin/stdout) через кольцевой буфер и WebSocket.
- Автозапуск, автоперезапуск с backoff, захват crash-report.
- Автоустановка: server jar, лоадер и JRE (Temurin) нужной версии ставит сам `admin-core`.
- Бэкапы мира: tar + zstd, по расписанию, с ретеншном.

### 2.2. Модпак
- Хранилище контент-адресуемое: `blobs/<aa>/<sha256>`. Манифест сопоставляет путь и хеш.
- При загрузке JAR определяется сторона (`client` / `server` / `both` / `unknown`):

| Лоадер | Источник | Надёжность |
|---|---|---|
| Fabric | `fabric.mod.json` → `environment` | объявлено |
| Quilt | `quilt.mod.json` → `minecraft.environment` | объявлено |
| Forge 1.13+, NeoForge | `mods.toml` / `neoforge.mods.toml`: `clientSideOnly`, `side` у зависимостей от игры и лоадера, `displayTest` | подсказка; чаще `unknown` |
| Forge 1.12.2 | `mcmod.info` + `@Mod(clientSideOnly / serverSideOnly)` | подсказка |

- Ручная классификация хранится по хешу содержимого и имеет приоритет. Файл со стороной `unknown` не попадает ни на сервер, ни в манифест, пока админ не решит.
- Источники модов: загрузка файлов, импорт `.mrpack` (сторона берётся из `env`), поиск и установка из Modrinth и CurseForge (API-ключ CurseForge вводит админ).
- Два представления набора файлов:
  - серверное: файлы со стороной `server` и `both` выкладываются в каталог инстанса (JAR — hardlink с откатом на копию, конфиги — копия);
  - клиентское: манифест из файлов со стороной `client` и `both`.

### 2.3. Политика чужих модов (на инстанс)
- `strict` — всё, чего нет в манифесте, удаляется перед запуском;
- `optional` — только файлы манифеста; помеченные `optional` игрок включает сам;
- `permissive` — лишние JAR игрока не трогаются.

Это контроль целостности набора, не античит: клиент остаётся под контролем игрока.

### 2.4. Авторизация и скины
- API по спецификации authlib-injector: meta-корень, `/authserver/*`, `/sessionserver/session/minecraft/join`, `/hasJoined`, `/profile/{uuid}`, `/api/profiles/minecraft`.
- Подпись свойства `textures` ключом, сгенерированным при первом запуске.
- MC-инстансы работают с `online-mode=true` и `-javaagent:authlib-injector` на локальный адрес `admin-core`. Учётные записи Microsoft не принимаются.
- Скины и плащи: PNG 64x64 или 64x32, модель classic/slim.

### 2.5. Учётные записи
- Ник + пароль (argon2id). Email не используется.
- Сброс пароля — одноразовый код, который админ выдаёт в панели.
- Политика регистрации: `strict_invite` (одноразовый инвайт), `approval_required` (вход после одобрения), `closed` (аккаунты создаёт админ).
- Инвайты случайные, в БД хранится только хеш.

### 2.6. Админка
- Vite SPA: React, shadcn/ui, темы tweakcn, раскладка bento grid. Вшита в бинарь.
- Все иконки анимированные.
- Разделы: дашборд, инстансы и консоль, файлы модпака с классификацией сторон, поиск модов, игроки и инвайты, тема лаунчера и новости, бэкапы.

## 3. launcher-client

Один бинарь на GPUI, раздаётся через GitHub Releases.

- **Discovery**: игрок вводит домен; SRV `_mcadmin._tcp.<домен>`, иначе `https://<домен>`; затем `GET /api/v1/handshake`.
- **UI**: раскладка фиксированная. Сервер задаёт палитру, шрифт, логотип, фон, ссылки и новости. Иконки анимированные.
- **Инстансы**: список с сервера, выбор в лаунчере. Каталог клиента: `<data_dir>/Relic/<sha256(домен)>/<instance_id>/`; `.minecraft` не затрагивается.
- **Установка игры**: version JSON Mojang, client jar, библиотеки, assets, natives; установка лоадера (Fabric, Quilt, Forge, NeoForge); JRE Temurin нужной major-версии в изолированный каталог.
- **Синхронизация**: параллельное хеширование, действия `Download` / `Update` / `DeleteOrphan` / `RetainLocal`; `sync_once` для конфигов; `protected_paths` не трогаются; проверка SHA-256 после загрузки; докачка по Range.
- **Запуск**: JVM с `-javaagent:authlib-injector.jar=<yggdrasil_url>`, токеном и UUID.
- **Токены**: в системном хранилище (`keyring`).
- **Самообновление**: из GitHub Releases с проверкой подписи minisign.

## 4. Версии

- Minecraft 1.12.2 и новее. Java 8, 17 или 21 по версии игры.
- Лоадеры: Fabric, Quilt, Forge, NeoForge.
- Сервер: Linux — основная платформа, Windows поддерживается.
- Лаунчер: Windows x64, Linux x64, macOS x64 и arm64.

## 5. Схемы

### 5.1. Discovery

```
_mcadmin._tcp.nightfall.my. 3600 IN SRV 10 5 8443 core.nightfall.my.
```

Сертификат TLS должен быть выпущен на целевой хост SRV-записи.

### 5.2. Манифест клиента

`GET /api/v1/instances/{id}/manifest`

  "java_runtime": { "major_version": 21, "vendor": "temurin" },

`build_id` меняется при любом изменении набора файлов, сторон или политики. Типы описаны в `crates/relic-proto`.

### 5.3. Handshake

`GET /api/v1/handshake` возвращает имя сервера, политику регистрации, адрес Yggdrasil, тему (`palette`, `font_url`, `logo_url`, `background_url`), ссылки и список инстансов.

## 6. Модель доверия

- Сервер раздаёт исполняемый код (моды). Вводя домен, игрок доверяет его владельцу так же, как при установке чужого модпака.
- Подлинность сервера обеспечивает TLS; без действительного сертификата лаунчер не подключается.
- Лаунчер обновляется только из GitHub Releases и только при верной подписи; сервер не может подменить бинарь лаунчера.
- Blob отдаётся клиенту, только если он входит в клиентский манифест запрошенного инстанса.

## 7. Что изменено относительно исходного PRD

| Было | Стало | Причина |
|---|---|---|
| Полный server-driven `LayoutDocument` | Тема и контент слотов, раскладка фиксированная | Объём и риск на GPUI |
| gRPC, HTTP/3 | REST/JSON + WebSocket, HTTP/2 + Range | Одного транспорта достаточно |
| SHA-256 и blake3 | Только SHA-256 | Один хеш в протоколе |
| Индекс по `path` | Хранилище по хешу, манифест путь→хеш | Дедупликация, докачка |
| «RFC-compliant Yggdrasil» | Спецификация authlib-injector | RFC не существует |
| Side из `mods.toml` как надёжный | Подсказка плюс ручная классификация | В формате нет стороны мода |
| Symlink в server `/mods` | Hardlink или копия | Symlink ненадёжен на Windows |
| Удаление любых лишних JAR | Политика `strict` / `optional` / `permissive` | Клиентские моды игроков |
| Device fingerprinting | Убрано | Хрупко, цель неясна |
| Один сервер | Несколько инстансов | Решение по итогам обсуждения |
| Fallback-порт 443 или 8443 | 443 | Противоречие в тексте |
| — | Установка MC и лоадера на клиенте | Отсутствовало |
| — | Автоустановка сервера, `.mrpack`, Modrinth, CurseForge | Отсутствовало |
| — | Самообновление лаунчера с подписью | Отсутствовало |
| — | Ник + пароль, сброс кодом от админа | Модель аккаунта не была описана |
